# 02. 1단계: 대본 입력

## 목적

사용자의 자유로운 아이디어를 세계관 뼈대 + 방향타 + 초기 에셋 목록으로 변환한다.

## 사용자 입력

텍스트 박스 하나에 자유 형식으로 기재한다. 구조화 불필요.

```
장르: 다크 판타지
분위기: 어둡고 긴장감 있는, 오케스트라풍 BGM
주인공: 카이 - 20대 남성 떠돌이 검객, 긴 검은 머리, 
  왼쪽 뺨에 흉터, 저주받은 붉은 수정검을 들고 다닌다
핵심 갈등: 과거에 지키지 못한 사람에 대한 죄책감
시작 장소: 항구 마을 비레
기타 캐릭터: 상인 보록 - 40대 뚱뚱한 약초 상인
몬스터: 그림자 늑대 - 밤에만 활동하는 안개 속 짐승
세계관 규칙: 수정에 영혼이 깃들 수 있다
```

## 처리 흐름 (2-Pass)

### Pass 1: 세계관 뼈대 생성

Node.js가 사용자 입력을 Handlebars 템플릿에 삽입하여 프롬프트 A를 조립한다.

**프롬프트 A 내용:**

```
아래 설정을 바탕으로 이 세계의 뼈대를 작성해라.

포함할 내용:
1. 세계관의 핵심 규칙 3~5개 (구체적으로)
2. 주인공의 내면 갈등과 외면 목표
3. 이야기가 향할 수 있는 큰 방향 2~3개 (확정이 아닌 가능성)
4. 시작 시점의 상황 묘사

에피소드별 줄거리는 쓰지 마라.

=== 사용자 제공 설정 ===
{사용자 입력 전문}
```

**사용자 동작:** 프롬프트 복사 → 외부 LLM 붙여넣기 → LLM 응답 복사 → 시스템에 붙여넣기

**시스템 처리:** 응답을 세계관 뼈대 텍스트로 저장하고 방향타(story_compass) 데이터를 구성한다. 이때 Prompt A의 실제 프롬프트 원문과 LLM 응답도 `script_stage_snapshots`에 저장하여 다음 접속 때 재검토할 수 있게 한다.

### Pass 2: 에셋 JSON 추출

Pass 1의 결과 + 원본 입력을 합쳐서 프롬프트 B를 조립한다.

**프롬프트 B 내용:**

```
아래 세계관에서 모든 명명된 자산을 JSON으로 추출해라.
JSON만 출력하고 다른 텍스트는 쓰지 마라.

형식:
[
  {
    "asset_id": "타입_영문이름",
    "asset_type": "CHARACTER | NPC | LOCATION | ITEM | MONSTER",
    "display_name": "한글 표시명",
    "appearance_prompt": "영어 외형 묘사 (Flux 렌더링용)",
    "audio_type": "TTS | SFX | NONE",
    "voice_hint": "음성 특성 한글 설명 (TTS인 경우)"
  }
]

=== 세계관 + 사용자 설정 ===
{Pass 1 응답 + 원본 입력}
```

**사용자 동작:** 동일한 복사-붙여넣기 루프

**시스템 처리:**
1. JSON 파싱 및 스키마 검증 (ajv)
2. 검증 실패 시 에러 표시, 사용자가 LLM에 재요청 가능
3. 검증 통과 시 에셋 목록을 화면에 표시
4. Prompt B의 실제 프롬프트 원문, 원응답, 마지막 파싱 결과/에러를 `script_stage_snapshots`에 저장한다.

## 에셋 확정

추출된 에셋 목록을 사용자에게 보여준다. 각 에셋마다 표시:

- 표시명
- 타입 (캐릭터/NPC/장소/아이템/몬스터)
- 시각 전략: PROMPT (전부 초기 상태)
- 음성: voice_hint 기반으로 음성 풀에서 자동 매칭된 결과

사용자가 할 수 있는 것:
- 개별 에셋 수정 (이름, 외형 묘사, 음성 등)
- 에셋 추가/삭제
- 음성 배정 변경

"확정" 시 모든 에셋이 DB에 등록된다.

## 방향타 (story_compass)

Pass 1의 결과에서 추출/구성되는 데이터. 마스터 대본이 아니라 나침반이다.

```
story_compass:
  genre: "다크 판타지"
  mood: "어둡고 긴장감 있는 오케스트라"
  protagonist_drive: "과거의 진실을 마주하려 하지만 두려워한다"
  world_rules: [
    "수정에 영혼이 깃들 수 있다",
    "그림자 짐승은 밤에만 활동한다",
    "그림자 짐승은 빛에 약하다"
  ]
  possible_directions: [
    "검의 저주가 카이를 완전히 잠식",
    "과거의 동료가 적으로 등장",
    "그림자 짐승의 근원이 카이 자신과 연결"
  ]
  tone_keywords: ["고독", "속죄", "어둠 속 한 줄기 빛"]
```

방향타는 고정이 아니다. 에피소드가 쌓이면서 갱신된다 (05-episode.md 참조).

## 2-Pass 분리의 이유

단일 프롬프트로 "대본도 쓰고 JSON도 추출해라"고 하면:
- 창작과 구조화를 동시에 요구하여 둘 다 품질 저하
- JSON 파싱 실패율 증가
- 마스터 대본 원본이 별도 보존되지 않음

분리하면:
- Pass 1은 순수 창작에 집중 → 세계관 품질 향상
- Pass 2는 이미 완성된 텍스트에서 추출만 → JSON 정확도 향상
- 세계관 뼈대가 별도 저장되어 향후 참조 가능

## 1단계 완료 후 DB 상태

```
프로젝트: 잿빛 숲의 복수
├── seed 원문: 저장됨
├── 방향타: 저장됨
├── 세계관 뼈대: 저장됨 (산문 텍스트)
├── Prompt A/B 원문 스냅샷: 저장됨
├── 에셋: 전부 visual_strategy=PROMPT, 음성 배정 완료
├── 에피소드: 없음
└── 기억 체계: 비어있음
```
