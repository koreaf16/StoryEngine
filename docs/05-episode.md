# 05. 4단계: 에피소드 만들기

## 목적

방향타 + 캐릭터 프로필 + 기억 체계를 조합하여 씬→샷 단위의 촬영 대본과 스냅 이미지를 생성하고, 사용자가 스토리보드 UI에서 리뷰한 뒤 확정한다.

## 에피소드 생성 모드

사용자가 에피소드 시작 시 택일:

- **자동**: "다음 화 만들어줘". 시스템이 알아서 생성
- **힌트 제공**: 한 줄 방향 제시. "카이가 과거 동료를 만났으면 좋겠어"
- **부분 대본**: 구체적 상황 기술. "카이가 숲에서 부상당한 여성 기사를 발견한다"

세 모드 모두 같은 파이프라인을 탄다. 차이는 LLM 프롬프트에서 사용자 입력의 비중.

## 내부 처리 흐름

```
1. 컨텍스트 조립
2. 골격 생성 (프롬프트 D) — 신규 에셋 감지 → 자동 등록 + 음성 배정
   └ 시네마틱 메타데이터 추가: color_palette, key_object, connection_device
3. 대본 생성 (프롬프트 D2) — 글이 먼저: 에피소드 전체 대사 한 번에
   └ 대사-영상 관계(complement/contrast/extend), 연기 디렉션, 감정 곡선
4. 씬별 샷 생성 (프롬프트 E) — 씬 수만큼 반복, D2 대사를 배치
   └ render_prompt 5블록 구조, 숏 리듬 설계, 프레이밍 심리
5. 씬별 사운드 설계 (프롬프트 F) — 씬 수만큼 반복
   └ 앰비언스, 음악 세그먼트, 폴리, TTS 디렉션, 믹싱 밸런스
6. 오토 바인딩 (LoRA/프롬프트 + 음성 + 효과음)
7. 스냅 이미지 생성 (각 샷마다 Flux)
8. 스토리보드 UI 표시
9. 사용자 리뷰 → 수정 → 확정
10. TTS 일괄 생성 → 음성 길이 검증 (F의 연기 디렉션 적용)
11. Export JSON 조립 (사운드 설계 데이터 포함)
12. 세계 상태 갱신 (벡터 + 그래프 + 방향타)
```

## 1. 컨텍스트 조립

3중 기억 소스를 우선순위대로 합산. 토큰 예산 초과 시 하위 순위부터 절삭.

| 우선순위 | 소스 | 에피소드 1 | 에피소드 2+ |
|----------|------|-----------|------------|
| 1 | 방향타 | 있음 (필수 고정) | 있음 (갱신됨) |
| 2 | 직전 화 요약 + 캐릭터 현재 상태 | 없음 | 있음 |
| 3 | 그래프 기억 (미해결 복선, NPC 행보) | 초기 상태만 | 있음 |
| 4 | 벡터 기억 (유사 과거 장면 top-k) | 비어있음 | 있음 |
| 5 | 사용자 힌트 | 있는 경우 | 있는 경우 |

에피소드 1은 특수 케이스: 벡터 비어있고 그래프도 초기 상태뿐. 방향타가 컨텍스트 대부분 차지.

### Redis 컨텍스트 캐시

직전 에피소드의 컨텍스트 조립 결과를 Redis에 TTL 30분 캐싱. 다음 에피소드 시작 시 변경 부분만 델타 업데이트.

## 2. 골격 생성 (프롬프트 D)

에피소드 전체의 씬 목록을 생성하는 가벼운 JSON.

### 씬 분할 원칙

- 씬 개수 제한 없음. 스토리가 요구하는 만큼 자유롭게 분할.
- **장소가 아니라 감정이 바뀔 때** 씬을 나눈다. 같은 방 안에서도 감정이 전환되면 새 씬.
- 스토리 흐름 우선: 서사 구조에 따라 씬을 나눈다. 정해진 틀에 스토리를 맞추지 않는다.
- 영상미 기반: 장소·분위기·시간 전환, 긴장감 변화 등 시네마틱 연출이 자연스러운 지점에서 나눈다.

### 시네마틱 메타데이터 (2026-04-05 추가)

각 씬에 추가된 시네마틱 필드:

| 필드 | 설명 | 예시 |
|------|------|------|
| `color_palette` | 씬의 지배적 색감 | `"desaturated blues"`, `"warm amber with crimson"` |
| `key_object` | 상징 오브젝트 | `"깨진 나침반"`, `"마르지 않는 촛불"` |
| `key_object_state` | 오브젝트 현재 상태 | `"온전함"`, `"금이 가기 시작"`, `"산산조각"` |
| `connection_device` | 다음 씬 연결 방식 | `match_cut`, `sound_bridge`, `motif_echo`, `hard_cut` |

**컬러 스크립트**: 에피소드 전체의 color_palette 흐름이 감정 곡선과 일치해야 한다.
예: 희망 씬 → 골드/웜톤 / 절망 씬 → 쿨블루 / 재생 씬 → 새벽 핑크

```
다음 세계관과 캐릭터를 바탕으로 에피소드 {N}의 씬 구성을 만들어라.

각 씬마다:
- 씬 번호와 장소 (asset_id)
- 등장 에셋 목록
- 핵심 사건 한 줄
- 분위기

사용 가능한 에셋 목록:
{DB에서 조회한 에셋 ID + 표시명}

새 에셋이 필요하면 신규 asset_id를 만들어서 써라.
JSON으로 출력.

=== 방향타 ===
{방향타}
=== 캐릭터 프로필 ===
{등장 예상 캐릭터들의 프로필}
=== 기억 ===
{컨텍스트 조립 결과}
=== 사용자 힌트 ===
{있는 경우}
```

### 신규 에셋 감지

골격 응답에서 DB에 없는 asset_id가 있으면:
1. 사용자에게 알림: "신규 에셋 감지: {이름}"
2. "확인" → 자동 등록 (PROMPT 상태) + 음성 배정 (TTS/SFX 자동 판단)
3. "이 캐릭터 빼고 다시" → 사용자가 프롬프트를 수정하여 재생성

## 2-1. 대본 생성 (프롬프트 D2) — 2026-04-05 신규

**"글이 먼저다"** 원칙. 골격 완료 직후, 샷 설계 전에 에피소드 전체 대사를 한 번에 생성한다.

### 왜 대본이 먼저인가

씬부터 만들면 각 씬이 "예쁜 장면"이 되지만 서로 연결되지 않는다. 대사를 나중에 끼워넣으면 영상에 대사를 맞추는 꼴이 되어, 말이 장면을 설명하는 느낌이 된다.

### D2 출력 구조

```json
[
  {
    "scene_number": 1,
    "emotion_arc": "불안→경계→신뢰의 실마리",
    "dialogues": [
      {
        "order_index": 0,
        "speaker_asset": "char_kai",
        "text": "대사 텍스트",
        "emotion": "경계",
        "intensity": 3,
        "timing_hint": "beat",
        "dialogue_visual_rel": "contrast",
        "acting_direction": "낮은 톤, 경계하며"
      }
    ]
  }
]
```

### 대사-영상 관계 (dialogue_visual_rel)

| 값 | 의미 | 예시 |
|----|------|------|
| `complement` | 화면이 대사를 보완 | 대사 "무섭다" → 화면: 공포의 원인 |
| `contrast` | 화면이 대사와 반대 | 대사 "괜찮아" → 화면: 떨리는 손 |
| `extend` | 화면이 대사 너머 여운 | 대사 "그 여름" → 화면: 녹아내리는 아이스크림 |

동어반복(대사가 화면을 그대로 설명)은 금지. 항상 보완/대조/확장 중 하나.

## 3. 씬별 샷 생성 (프롬프트 E)

골격의 각 씬에 대해 상세 샷을 생성. 씬 수만큼 프롬프트 E를 반복.

### render_prompt 5블록 구조 (2026-04-05 강화)

render_prompt를 반드시 다음 5블록 순서로, 쉼표로 구분하여 작성한다:

1. **[카메라/렌즈]**: 샷 사이즈 + 앵글 + 렌즈 특성 (예: `medium close-up, low angle, 85mm anamorphic, shallow depth of field`)
2. **[주체/행동]**: 인물 배치 + 현재 동작 + 표정 (현재진행형으로)
3. **[환경/공간]**: 장소 + 대기 효과 + 질감
4. **[조명]**: 방향 + 색온도 + 강도
5. **[미학/그레이딩]**: 색감 스타일, 씬의 color_palette 반영

**핵심**: 이미지 AI는 이전 샷을 모른다. 각 render_prompt는 독립적으로 읽혀도 완결된 장면이어야 한다.

### 숏 리듬 원칙 (2026-04-05 추가)

균일한 컷(5초-5초-5초)은 양산형. 완급 조절이 시네마틱을 만든다:
- 긴장 고조: 6초→4초→3초→2초 (가속)
- 해소: 2초→3초→5초→8초 (감속)
- `framing_rationale`: 구도의 심리적 이유 (예: "low angle — 인물의 권위감 강조")
- `rhythm_note`: 샷 리듬 의도 (예: "앞 빠른 컷 후 이 샷에서 숨 고르기")
- `connection_to_next`: 다음 샷/씬과의 시각적 연결 (매치컷 기회)

### 대사 배치 (D2 연동)

D2에서 생성된 대사를 샷에 배치만 한다. 텍스트 수정 금지.
`dialogue_visual_rel`을 보고 구도를 결정:
- `contrast`: 화자가 아닌 다른 것을 보여주는 구도 선택

### 대화 연출 원칙

대화 씬에서 싱글 샷만 나열하면 독백처럼 보인다. 반드시 구도를 섞어야 한다:
- **씬 진입**: two-shot으로 두 사람의 위치 관계 확립
- **말하는 사람**: OTS 또는 medium close-up
- **반응하는 사람**: reaction close-up (표정 변화)
- **클라이맥스**: extreme close-up (눈, 손, 소도구)

### 스토리 연속성 원칙

- 캐릭터 감정 흐름: 이전 씬에서 이어받아 이 씬 안에서 변화시킨다
- 물리적 연속성: 부상, 소지품, 의상 상태가 샷마다 유지되어야 한다
- 공간적 연속성(180도 규칙): 캐릭터 위치 관계를 씬 내에서 일관되게 유지한다

### 프롬프트 E에 전달되는 에셋 정보

- `appearance_prompt`: 얼굴/피부/머리 묘사 (render_prompt에 녹여서 사용)
- `outfit_prompt`: 의상 묘사 (render_prompt에 의상으로 반영)
- `personality.core_trait`: 핵심 성격 (표정/자세 묘사에 활용)
- `personality.emotional_pattern`: 감정 표현 방식
- `backstory.wound`: 내면 갈등 (감정 상태 묘사에 활용)
- `speech_style.tone`: 말투 톤 (대사 연기 방향)

2-레벨 생성의 이점:
- 레벨 1(골격)이 전체 구조를 잡아 씬 간 연결 유지
- 레벨 2의 JSON이 씬 단위로 짧아 검증 실패 시 해당 씬만 재시도
- 특정 씬이 마음에 안 들면 그 씬만 다시 돌릴 수 있음

## 3-1. 씬별 사운드 설계 (프롬프트 F) — 2026-04-05 신규

씬별 샷 완료 후, 해당 씬의 4레이어 오디오 아키텍처를 설계한다.

### 4레이어 구조

```
Layer 4  내레이션/대사 (TTS)    ← 볼륨 기준점 (0 dB)
Layer 3  음악 (스코어/BGM)      ← -12 ~ -18 dB
Layer 2  폴리/효과음 (SFX)      ← -6 ~ -10 dB
Layer 1  앰비언스 (공간음)       ← -20 ~ -24 dB
```

### F 출력 구조

```json
{
  "scene_number": 1,
  "ambience": "항구의 낮 — 파도, 갈매기, 나무 삐걱거림",
  "music_segments": [{ "shot_range": [1,3], "mood": "tense strings", "intensity": 6, "swell_point": "shot 2 중반", "silence_point": null }],
  "foley_map": [{ "shot_number": 1, "sfx": ["footsteps_gravel"], "sync_note": "걸음에 맞춰" }],
  "design_sfx": [{ "shot_number": 2, "sfx": "low_rumble", "purpose": "불길한 느낌" }],
  "sound_bridges": "씬 끝 — 검의 공명음이 다음 씬 고요한 숲으로 페이드",
  "tts_direction": [{ "dialogue_index": 0, "speed": 0.9, "pre_gap_ms": 300, "post_gap_ms": 500, "acting_note": "낮고 건조하게" }],
  "mix_balance": { "narration_db": -3, "music_db": -12, "sfx_db": -8, "ambience_db": -18, "exceptions": "" }
}
```

**핵심 원칙**: 가장 강렬한 순간에 음악을 빼는 것이 아마추어와 프로의 차이다.

## 4. 오토 바인딩

생성된 샷의 referenced_assets를 DB에서 조회하여 실행 가능한 지시서로 변환.

상세: [07-asset-lifecycle.md](07-asset-lifecycle.md)의 오토 바인딩 섹션 참조.

## 5. 스냅 이미지 생성

각 샷의 `render_prompt`를 Flux에 넣어 프리뷰 이미지를 생성.

> 운영 메모: 8189 A100 서버는 `--normalvram`으로 기동한다.

- 오토 바인딩 완료 상태이므로 LoRA 있는 에셋은 LoRA 적용
- 비율/크기: 1024×576 (16:9, Wan 2.2 I2V 시작 프레임 표준)
- 최종 영상과 동일 품질일 필요 없음. 프리뷰 + Wan 2.2 I2V 시작 프레임 용도
- GPU 큐: `gpu:realtime` (최우선)

### 참조 파이프라인 (fluxSnap.js)

1. **LoRA 체인**: LORA_TRAINED 에셋 → trigger_word + LoRA 가중치 적용
   - LoRA가 없는 에셋은 텍스트 프롬프트(appearance_prompt)로 폴백
2. **ModelSamplingFlux**: LoRA 체인 이후 Flux 1 Dev용 타임스텝 시프트 패처 적용

## 6. 스토리보드 UI

### 전체 보기

씬별로 그룹핑된 샷 카드 목록. 각 카드에:
- 스냅 이미지 썸네일
- 샷 번호
- 장면 설명 한 줄
- 카메라 모션 태그
- 장면 길이
- 전환 효과
- 대사 첫 줄 (있는 경우)
- 바인딩 상태: LoRA/PROMPT 뱃지

### 샷 상세 (카드 펼침)

- 스냅 이미지 원본
- 렌더링 프롬프트 전문
- 카메라 모션
- 대사 전문 (화자별 색 구분, voice_id 표시)
- BGM 태그
- 효과음 목록
- 장면 길이 / 전환 효과
- 바인딩된 에셋 목록 (각 에셋의 LoRA/PROMPT 상태)

### 편집 기능

- 대사 수정
- 카메라 모션 변경
- 스냅 이미지 재생성
- 샷 순서 변경 (드래그)
- 샷 삭제 / 추가
- TTS 미리듣기 (개별 대사 단위)

## 7. 에피소드 확정

"에피소드 확정" 버튼 → 후처리 파이프라인:

1. **TTS 일괄 생성**: 모든 대사를 음성 파일로 변환 (상세: [08-audio-system.md](08-audio-system.md))
2. **음성 길이 검증**: 대사 음성 길이 > 해당 샷 duration_sec이면 경고. 선택지: 대사 줄이기 / 장면 길이 변경
3. **Export JSON 조립**: 샷 정보 + 스냅 이미지 경로 + TTS 파일 경로 + 립싱크 플래그 (상세: [09-export-json.md](09-export-json.md))
4. **세계 상태 갱신** (아래 참조)

## 8. 세계 상태 갱신

에피소드 확정 후 자동 실행:

### 벡터 DB
각 샷의 `narrative_note`와 `render_prompt`를 임베딩하여 저장. 향후 에피소드에서 유사 장면 검색 시 활용.

### 그래프 DB
- 캐릭터 상태 갱신 (위치, 감정, 관계 변화)
- NPC 행보 기록 ("보록이 항구로 이동해 약초 매입")
- 스토리 노드 추가 ("카이가 혈석검의 힘을 각성" → 복선)

### 방향타 갱신
에피소드 결과를 반영하여 방향타 업데이트를 위한 프롬프트 생성. 사용자가 LLM에 넣고 결과를 확인/수정 후 반영.

- 새로 열린 가능성 추가
- 닫힌 가능성 제거 또는 약화
- 변화된 캐릭터 동기 반영

### Redis 캐시
이번 에피소드의 컨텍스트 조립 결과 캐싱 (TTL 30분). 다음 에피소드 시작 시 델타 업데이트.
