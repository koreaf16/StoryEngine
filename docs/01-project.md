# 01. 프로젝트 관리

## 프로젝트란

프로젝트는 시스템의 최상위이자 유일한 단위이다. 하나의 프로젝트 = 하나의 작품이다. 프로젝트 간에는 아무것도 공유하지 않는다.

## 프로젝트가 품는 것

```
프로젝트
├── 프로젝트 설정 (장르, 분위기, 임계값 등)
├── 방향타 (세계관 뼈대, 가능한 방향들)
├── 에셋 전체 (캐릭터, NPC, 장소, 아이템, 몬스터)
│   ├── 각 에셋의 프로필, 외형, 음성
│   └── 등장 횟수, 승격 상태
├── 에피소드들
│   ├── 에피소드 1 (씬 → 샷 → 스냅 이미지, 상태: 확정됨)
│   ├── 에피소드 2 (상태: 리뷰 중)
│   └── ...
├── 기억 체계
│   ├── 벡터 DB (과거 장면들)
│   ├── 그래프 DB (인과관계, NPC 행보)
│   └── 직전 화 요약
└── 음성 풀 배정 현황
```

## 프로젝트 간 격리

- 에셋: A 프로젝트의 카이와 B 프로젝트의 카이는 완전히 별개
- 음성 풀: 중복 검사는 프로젝트 안에서만 적용. A에서 쓴 음성을 B에서도 쓸 수 있음
- 기억 체계: 벡터/그래프 DB 모두 project_id로 필터링
- 설정값: face_threshold, rag_top_k 등 프로젝트마다 개별 설정 가능

## GPU 큐와 프로젝트

GPU 큐(BullMQ)는 시스템 전체에서 공유한다. 단, 모든 작업에 project_id가 태깅되어 어떤 프로젝트의 작업인지 구분된다. 사용자가 A 프로젝트 에피소드를 돌리면서 B 프로젝트의 에셋 앵커 생성을 걸 수도 있고, 큐가 우선순위대로 처리한다.

## 프로젝트 설정 (project_config)

| 설정 | 기본값 | 설명 |
|------|--------|------|
| face_threshold | 0.4 | 얼굴 유사도 필터 임계값 (낮을수록 엄격) |
| rag_top_k | 5 | 벡터 검색 시 가져올 과거 장면 수 |
| derivative_count | 15 | 파생 이미지 프리셋 수 |

예: 극사실주의 프로젝트는 face_threshold=0.3, 만화풍은 0.55

## UI: 프로젝트 목록 화면

시스템 접속 시 첫 화면. 각 프로젝트 카드에 표시되는 정보:

- 프로젝트 제목
- 장르 태그
- 현재 에피소드 수
- 등록된 에셋 수
- 마지막 작업일
- 진행 상태 (대본 입력 / 캐릭터 / 외형 / 에피소드 진행 중)

동작:
- "새 프로젝트" → 제목 입력 후 1단계(대본 입력)로 진입
- 기존 프로젝트 클릭 → 해당 프로젝트의 현재 단계로 진입
